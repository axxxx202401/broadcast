# 中文注释评审清单

本清单依据[全项目详细中文注释设计](../superpowers/specs/2026-09-03-project-chinese-comments-design.md)，用于评审项目自有源码、测试、协议定义和构建脚本的注释变更。

## 通用

- [ ] 变更未触及 `target/`、`node_modules/`、`dist/`、`prost` 生成代码、`vendor/gt4.js`、锁文件或纯资源等排除范围。
- [ ] crate、模块及重要文件说明了职责、边界和主要依赖。
- [ ] 公开 API 说明了用途、参数、返回值、错误条件、副作用和调用约束。
- [ ] 复杂私有逻辑说明了状态转换、不变量、并发或生命周期约束、重试与失败处理。
- [ ] 测试应表达场景意图；仅对复杂准备过程和非自明断言补充必要注释。
- [ ] 有价值的英文说明已准确翻译为简体中文，未丢失协议细节或设计依据。
- [ ] 协议名、字段名、HTTP 头、算法标识保持英文，注释与 `proto/broadcast.proto`、实现及测试一致。
- [ ] 没有机械复述语法、逐行翻译或无法验证的推测性注释。
- [ ] 变更只涉及注释或注释约束，没有混入业务行为修改。

## 验证

- [ ] `cargo fmt --all --check` 通过。
- [ ] 对应 Rust crate 的测试和 Clippy 检查通过。
- [ ] 已完成注释基线的 crate 在其 `Cargo.toml` 的 `[lints.rust]` 中启用 `missing_docs = "warn"`，且无新增 `missing_docs` 警告；`prost` 生成模块按需局部豁免，workspace 初期未启用 `deny`。
- [ ] 涉及前端时，typecheck、单元测试和生产 build 均通过。
- [ ] 已抽查注释与实现、协议定义及测试行为一致，并确认测试结果没有因纯注释变更而变化。
