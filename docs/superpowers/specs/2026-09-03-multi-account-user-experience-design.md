# 多账号与普通用户体验设计

## 1. 目标

为 IM Monitor 增加适合普通用户使用的多账号能力，并简化登录页和监控页：

- 应用启动后优先恢复最后使用的账号；
- Token 仍有效时直接进入应用，不要求再次登录；
- 保存所有登录成功的账号，安全保存密码登录账号的密码；
- 支持在应用头部切换账号并显示当前邮箱或账号；
- 在“全部群消息”中汇总展示正在监控的 groupId；
- 删除登录页的步骤说明和 `secondMac`；
- 改善窗口自适应和滚动条样式，减少不必要的技术信息。

本设计不改变远端登录协议，也不尝试绕过 GT4、短信验证码、邮箱验证码或服务端二次验证。

## 2. 已确认的产品行为

### 2.1 启动与退出

- 应用记录最后使用的账号。
- 启动时读取该账号保存的 Token，并通过用户详情等轻量接口验证。
- Token 有效时恢复会话、账号数据库和聊天连接，直接进入主界面。
- Token 无效时删除该 Token，进入已选择对应账号的登录页。
- 用户点击“退出登录”时清除当前账号的 Token，但保留账号记录和加密密码。
- 即使系统凭据库删除失败，账号索引也立即标记为已退出，后续启动不得自动使用残留 Token。
- 退出后不再自动进入主界面；登录页默认选中刚退出的账号。

### 2.2 多账号

- 保存所有成功登录的手机号或邮箱账号。
- 密码登录成功后保存密码；验证码登录只保存账号信息和 Token，不保存验证码。
- 在主界面头部选择其他账号时，先尝试使用目标账号的 Token。
- 目标 Token 无效时进入登录页，自动选择该账号，并呈现已保存密码状态。
- “移除此账号”删除账号索引、Token 和密码，但保留该账号的本地 SQLite 数据。
- 同一账号以后重新登录时，通过 UID 重新关联已有 SQLite 数据。

### 2.3 登录页

- 默认使用“邮箱 + 密码”登录。
- 已保存账号通过账号选择框切换。
- 手机号密码、手机号验证码和邮箱验证码收纳到“其他登录方式”。
- 删除右侧步骤说明。
- 删除 `secondMac` 输入项及前后端提交字段。

## 3. 凭据与账号索引

### 3.1 安全边界

采用“系统凭据库 + 普通账号索引”方案：

- macOS 使用 Keychain；
- Windows 使用 Credential Manager；
- Linux 使用 Secret Service；
- 持久化 Token 和密码只能保存在系统凭据库中；
- 用户本次手动输入的密码只允许短暂存在于登录表单和必要的 Rust 内存中，用完后释放；
- Token 和密码不得写入 SQLite、前端持久化存储、日志或错误文本；
- 系统凭据库不可用时禁止降级为明文文件，只提示本次无法安全记住登录信息。

账号索引可以保存以下非密钥信息：

- UID；
- 用户输入的手机号或邮箱；
- 登录方式；
- 最后使用时间；
- 是否存在已保存密码；
- 是否存在 Token；
- 是否为最后使用账号。

账号索引不保存密码掩码、Token 摘要或可用于还原密钥的数据。

### 3.2 凭据键

系统凭据库中的条目以应用固定 service 和 UID 标识账号：

- Token 条目：`im-monitor.token` + UID；
- 密码条目：`im-monitor.password` + UID。

登录成功并取得 UID 后再写入凭据，避免使用可变邮箱、手机号或登录方式作为密钥。账号索引负责从用户可见账号映射到 UID。

### 3.3 前端密码展示

前端不读取已保存密码的明文：

- 选择有密码的账号后，密码框显示“已保存密码”的不可还原状态；
- 用户直接提交时，由 Rust 从系统凭据库读取密码并执行验证流程；
- 用户开始输入新密码时，清除“使用已保存密码”状态；
- 新密码登录成功后覆盖该账号原有密码；
- 登录失败时不删除密码，只有服务端明确判定密码错误时才取消自动使用状态并要求重新输入。

## 4. 每账号独立 SQLite

### 4.1 目录模型

每个 UID 使用独立数据库。以 macOS 用户目录为例：

`/Users/<user>/.im-monitor/accounts/<uid>/im_monitor.db`

数据库继续保存该账号的：

- 群组快照；
- 监控选择；
- 历史消息；
- 用户密钥对。

公共应用状态不保存到账号数据库。账号索引和最后账号信息放在独立的非敏感配置文件中。

### 4.2 数据库生命周期

- 未登录时不打开账号业务数据库。
- 登录成功或 Token 恢复成功后，根据 UID 打开对应数据库。
- 账号切换时停止旧连接、取消旧异步任务并关闭或释放旧数据库句柄，再打开目标账号数据库。
- “移除此账号”不删除数据库目录。
- 本设计不在普通界面提供“删除本地消息”功能，避免误删；如未来增加，必须二次确认。

### 4.3 旧数据库迁移

旧数据库位于应用原有数据目录，且没有账号归属信息。升级后的首次成功登录执行一次迁移：

1. 如果目标 UID 数据库不存在，则复制旧数据库到目标账号目录；
2. 迁移成功后保留旧数据库备份；
3. 写入迁移完成标记，避免后续账号重复导入；
4. 如果复制、校验或打开失败，继续保留原文件并向用户显示可恢复的错误；
5. 如果目标数据库已存在，不覆盖目标数据。

由于旧数据无法可靠推断 UID，它会归属升级后第一个成功登录的账号。保留备份用于处理账号选择错误或迁移失败。

## 5. 会话恢复与账号切换

### 5.1 启动恢复

前端启动期间显示简洁的“正在恢复上次登录”状态，不先闪现登录页。

Rust 恢复流程：

1. 读取最后账号索引；
2. 从系统凭据库读取该 UID 的 Token；
3. 调用用户详情等接口验证 Token；
4. 验证成功后打开账号数据库；
5. 同步远端群组并恢复该账号监控选择；
6. 发布 `AuthSession`；
7. 启动聊天连接；
8. 返回当前账号、UID、群组及连接状态。

任一步失败都不得留下半初始化会话。Token 被明确判定无效时删除 Token；网络暂时不可用时保留 Token，并允许用户重试或进入登录页。

### 5.2 切换账号

账号切换复用现有 generation 并发门禁：

1. 增加 generation，使旧账号未完成的请求全部失效；
2. 断开旧聊天连接；
3. 清理旧 `AuthSession`、消息解密状态和前端消息；
4. 释放旧账号数据库；
5. 恢复目标账号 Token；
6. 成功后打开目标数据库并连接；
7. Token 失效时进入目标账号的预填登录状态。

切换期间禁用重复操作并显示“正在切换账号”，防止快速点击造成连接和数据串用。

### 5.3 退出与移除

- 退出登录：清除当前 Token、停止连接和会话，保留账号、密码及 SQLite。
- 移除此账号：在退出流程基础上删除账号索引和系统凭据库中的 Token、密码，保留 SQLite。
- 移除最后使用账号后，选择剩余账号中最近使用的一个作为登录页默认账号；没有账号时使用空白邮箱密码表单。

## 6. 界面设计

### 6.1 登录页

登录页使用简洁单栏卡片。没有已选账号或添加新账号时，默认展示：

- 应用 Logo 和一句用途说明；
- 已保存账号选择框；
- 邮箱输入框；
- 密码输入框或“已安全保存密码”状态；
- 主按钮“登录”；
- 次级入口“其他登录方式”。

展开“其他登录方式”后才能选择手机号密码、手机号验证码和邮箱验证码。GT4、验证码和服务端二次验证只在流程需要时出现，不提前展示协议步骤、validateToken 等技术信息。

错误信息转换为普通用户能够处理的提示，例如“密码不正确”“验证码已过期”“网络连接失败，请重试”。协议错误码只进入脱敏后的诊断日志，不作为主文案显示。

### 6.2 主界面头部

头部主要展示当前邮箱或手机号，UID 作为次要信息放入账号菜单。账号菜单包含：

- 当前账号；
- 其他已保存账号；
- 添加账号；
- 退出登录；
- 移除此账号。

连接状态使用“已连接”“连接中”“已断开”等普通文案，减少协议和开发术语。

### 6.3 全部群消息的 groupId

“全部群消息”标题下增加正在监控的群 ID 汇总：

- 默认最多展示 5 个 groupId；
- 超过 5 个时显示“另有 N 个，展开全部”；
- 展开后显示全部 ID，并提供“收起”；
- 没有监控群时显示“尚未选择监控群”；
- 每条消息原有的所属群名称和 groupId 继续保留，便于识别消息来源。

汇总区只展示正在监控的群，不受侧栏搜索词影响。

### 6.4 自适应和滚动

- 应用根容器占满窗口，禁止整页滚动。
- 只保留群列表和消息列表两个业务滚动区域。
- 正常桌面宽度采用侧栏加消息区布局。
- 窄窗口将群列表改为可展开侧栏，默认优先显示消息。
- 消息行在窄窗口隐藏次要标签，时间、群来源和正文保持可见。
- 文本和附件必须允许收缩或换行，不产生横向滚动条。
- 登录表单在窗口高度不足时允许卡片内部滚动，确保操作按钮可达。
- Chromium/WebViewKit 使用细窄深色滚动条；Firefox 兼容 `scrollbar-width` 和 `scrollbar-color`。
- 滚动条默认低对比度，悬停和拖动时提高对比度，并保留足够的可点击宽度。

## 7. 组件与后端边界

### 7.1 Rust

新增独立职责：

- 账号索引仓储：管理非敏感账号资料和最后账号；
- 凭据仓储：封装系统凭据库读写；
- 账号数据库管理器：按 UID 打开、切换和迁移 SQLite；
- 会话恢复服务：验证 Token 并恢复完整运行状态。

认证命令继续负责 issued、verify、login 和 challenge。账号保存与会话发布在登录成功后统一完成，避免不同登录分支产生不一致状态。

### 7.2 Vue

前端只接收可展示的账号摘要：

- UID；
- 显示账号；
- 登录方式；
- 是否有保存密码；
- 是否为当前账号。

前端提交“使用保存密码”标志，而不是保存密码值。账号选择、启动恢复和账号切换状态分别封装，避免继续扩大根组件职责。

## 8. 异常处理

- 凭据库不可用：允许手动登录，不保存 Token 和密码，显示一次非阻塞提示。
- Token 无效：删除该 Token，进入对应账号登录页。
- 网络不可用：保留 Token，提供重试和手动登录入口。
- 账号数据库损坏：停止进入主界面，保留文件并提示用户重试或联系支持，不自动删除。
- 旧数据库迁移失败：保留原文件和目标临时文件信息，不写迁移完成标记。
- 账号切换失败：保持无活动会话状态，不回退到可能已断开的旧账号。
- 保存密码失败：登录仍成功，但明确提示密码没有被保存。
- 登出清 Token 失败：立即将账号标记为已退出并清理运行时会话，提示本机凭据可能仍存在，允许再次清除。

## 9. 测试与验收

### 9.1 Rust

- 凭据仓储使用内存替身验证保存、覆盖、删除和不可用分支；
- Token 有效、无效、网络失败三种启动恢复；
- 多账号切换不会发布旧 generation 的结果；
- 每个 UID 打开不同 SQLite 路径；
- 切换账号后群组、监控状态和消息互不串用；
- 旧数据库迁移成功、目标已存在、复制失败及重复启动；
- 退出仅删除 Token，移除账号删除凭据但保留 SQLite；
- 日志和结构化错误不包含 Token 或密码。

### 9.2 Vue

- 登录页默认邮箱密码模式；
- 已保存账号选择和“已保存密码”状态；
- 其他登录方式展开；
- 页面不再显示步骤说明和 `secondMac`；
- 启动恢复期间不闪现登录页；
- 头部展示当前账号并可切换；
- groupId 汇总在 5 个以内直接展示，超过后可展开和收起；
- 窄窗口侧栏行为及消息次要信息隐藏；
- 账号切换、退出和移除账号的交互状态。

### 9.3 手工验收

在 Windows、macOS 和带 Secret Service 的 Linux 桌面环境分别验证：

1. 密码登录成功后重启应用，Token 有效时直接进入主界面；
2. Token 失效时出现已选择账号及保存密码状态；
3. 两个账号的数据分别写入不同 SQLite；
4. 切换账号不会短暂显示另一账号的消息；
5. 退出后重启停留在登录页；
6. 移除账号后本地 SQLite 仍存在；
7. 系统凭据库中可以找到 Token 和密码条目，普通配置和 SQLite 中找不到明文；
8. 常见窗口尺寸下没有整页或横向滚动条；
9. 群列表和消息列表滚动条与深色界面一致；
10. 全部群消息页面可以查看、展开和收起全部监控 groupId。

## 10. 非目标

- 不实现云端账号同步；
- 不跨系统迁移密码和 Token；
- 不自动绕过验证码或二次验证；
- 不在本次设计中增加远端 Token 刷新协议；
- 不自动删除任何账号的本地消息数据库；
- 不把普通配置中的邮箱或手机号描述为加密秘密；
- 不重构与多账号、登录和界面自适应无关的业务模块。
